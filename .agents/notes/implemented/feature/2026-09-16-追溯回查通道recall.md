# Agent Note: 追溯回查通道（recall）——让 agent 查自己的历史
Status: implemented
Class: feature

## 背景
追溯库此前只有「给人看」的消费面（看板 + trace-report）。agent 自己反而查不了：被审批拒绝后，
它不知道这个路径历史上被拦过几次、当时为什么；改一个文件前，它不知道这个文件有过合规未过记录。
而 events.jsonl 与决策笔记本来就是机器可读的——缺的只是一个面向 agent 的查询口。这是把追溯从
「事后验尸」升级成「agent 的经验记忆」的第一步。

## 决策
新增 `.agents/runner/recall.mjs`（CLI，纯读盘，消费既有 events.jsonl 与 index.notes，零新增数据
格式）：`--path`（文件历史 + 相关笔记）、`--rule`（检查器台账）、`--denied`（按目标聚合的被拦
清单）、`--notes`（笔记清单）、`--json`（机器可读）。三条硬约定：
- **永远 exit 0**：回查是查询不是闸门，失败/空结果如实输出，不阻断干活中的 agent（与
  hook-recorder 的红线同哲学）；
- 路径匹配按「剥会话前缀 + 双向 endswith」归一，容忍带不带 `.agents/trace/<会话>/` 前缀；
- 命中记录的目标一律从 parent 事件解出（`acp_message.params.path` 或 `payload.path` 两个位置都试），
  与 trace-index buildDigest 的解法同构。

提示词条款落在 `AGENTS.md §5`（改文件前/被拦后/写合规代码前先查），查询语义固定在
`SPEC §5.9`，契约测试 `.agents/runner/tests/recall-test.mjs`（合成样本 10 项）。

## 放弃方案
做成宿主内的 ACP 方法（agent 走协议查）：宿主要改协议面、agent 要等 initialize 协商，而且
recall 的价值场景常常是「会话还没开始 / 直开无宿主」时也该能查。CLI 与 trace-report 同构，
`--json` 输出对提示词稳定可用——AGENTS.md 就是提示词，写死命令行比依赖协商能力可靠。

让 agent 直接翻 events.jsonl：每会话文件 MB 级、格式是 envelope+payload 混合体，翻一次的
token 成本远超一次 `--json`；且「被拒目标要从 parent 解出」这种口径每个 agent 每次都要自己
重新发现，不如固化成一个工具。

## 代价与后果
收益：agent 动手前能问历史——同一坑不踩第二遍；被拦后能自查同类操作的处理记录；整个系统从
「人监督 agent」向「agent 从自己历史学习」迈出一步。
代价：多一个要维护的查询面（口径必须与 trace-index/pitfalls 同步——解 parent 的写法两边一致，
契约测试钉住）；查询走全文扫描（每会话 O(events)），库大了以后如需提速再建倒排，现在不必。
