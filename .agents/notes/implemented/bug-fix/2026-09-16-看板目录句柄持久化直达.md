# Agent Note: 看板目录句柄持久化免重选直达
Status: implemented
Class: bug-fix

## 背景
owner 实测反馈：刷新后点「最近打开」的目录条目只弹「目录需要重新选一次（浏览器不给长期句柄）」，
不能直接打开。上一轮把 webkitdirectory 的 File 句柄当成不可持久化，做了「标 needsReselect +
点卡片唤起重选」的兜底（见 [看板目录条目一键重开](2026-09-16-看板目录条目一键重开.md)），
但这个「浏览器不给」的结论只对 webkitdirectory 成立——File System Access API 返回的
FileSystemDirectoryHandle 可以结构化克隆，当时因宿主内核支持度未实测而推迟。

## 决策
选目录通道升级为 FSA 优先：`showDirectoryPicker({mode:'read'})` 返回的句柄结构化克隆进
IndexedDB 句柄库（键 = 条目键 `dir:<label>`；句柄库与条目库分开，条目库的 localStorage
通道走 JSON.stringify，存不住句柄）。重开分两态：

- 点击路径（openEntry）：`handleGet` 取句柄 → `ensurePermission`——`queryPermission`
  已放行就直接读，还在 prompt 就借这次点击的手势 `requestPermission` 要权，授权后读；
- 启动自动恢复（restoreLibrary）：只查 `queryPermission` 不问权——启动时没有用户手势，
  `requestPermission` 必抛 SecurityError；没放行就留给空态 CTA 的下一次点击去要权。

老内核没有 `showDirectoryPicker` 或调用被禁（非 AbortError）时退回 webkitdirectory
旧通道，条目仍标 needsReselect；FSA 扫描限定 `.agents` 子树（根下有 `.agents` 就只扫它，
node_modules/.git 不陪跑），整树兜底加 5 万文件闸。

## 放弃方案
继续 webkitdirectory + 永远重选。它最强的理由是行为最简单、完全不碰权限流；但 owner 明确
要「直接打开」，且支持度疑虑已被实测消除（无头 Chrome 于 file:// 源：`showDirectoryPicker`
存在、OPFS 建目录树、句柄进 IDB 跨 reload 复活、`queryPermission` 直接 granted），
「内核不支持」从疑虑降级成只剩老内核的兜底分支。另一方案把句柄直接塞进条目一起存也被否：
条目库要走 `JSON.stringify`（spark.db/localStorage），句柄会被打回空壳。

## 代价与后果
收益：刷新后点「最近打开」一键直达——授权已持久（Chrome 122+ 可选「每次访问都允许」）时零弹窗，
未持久时首次点击弹一次授权后直达。代价三条：1) 多一层 IndexedDB 依赖，句柄库写失败时条目会
「标了 hasHandle 却取不到句柄」，此时如实提示重选，不算静默坏；2) 旧 needsReselect 条目不会被
静默升级，用户要再走一次选择器才换成 FSA 通道；3) 目录条目键沿用 label（目录名），同名目录
仍会碰撞——沿用旧口径未改。验证：ui-smoke 107/107（新增 7 条 FSA 用例：OPFS 真句柄全链路）、
契约 13/13、图标 15/15。Trace: 本轮未过宿主（直开会话），无协议留痕。
