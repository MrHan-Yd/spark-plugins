# Agent Note: 看板宿主环境跳过 FSA 选择器
Status: implemented
Class: bug-fix

## 背景
owner 真机反馈（2026-09-17）：Spark 里装上看板，点「选择项目目录…」能弹出系统目录选择框，
确认后看板毫无反应——不加载、不报错、也不退回旧选择器。

上一轮（[看板目录句柄持久化直达](2026-09-16-看板目录句柄持久化直达.md)）把选目录通道升级为
FSA 优先，内核支持度的核销依据是**无头 Chrome 的 file:// 源**，Spark 宿主（WebView2）真机
从未实测。WebView2 对 File System Access API 的行为与 Chrome 有已知差异：选完目录后触发
二次权限弹窗（WebView2Feedback #3121）、权限提示依赖宿主处理（#2427）——宿主没处理时
promise 可能不按规范 reject，而看板只把「非 AbortError 的拒绝」当故障退回旧通道，
AbortError 一律当用户取消静默吞掉，promise 挂起更是无任何后续——正好是「没反应」。

## 决策
`pickDirectory` 改为双通道取舍：宿主环境（`window.spark` 存在）一律跳过 FSA，直接走已实测的
webkitdirectory 通道；FSA 只留给无宿主的浏览器预览模式（那条路句柄能进 IndexedDB、刷新后
免重选直达，收益保留）。另加 60 秒看门狗：promise 不 settle 也不许哑等，到期自动退回 legacy
选择器；触发后迟到的 settle 用 `fell` 标志丢弃，防二次弹框。

代价：Spark 用户每次开窗要重选一次目录（webkitdirectory 的 File 句柄刷新即失效，WebView2
亦然），帮助抽屉的「本地目录」行文案已同步改准，不再暗示宿主内句柄会记住。

## 放弃方案
保持 FSA 全局优先。它最强的理由是 fallback 链路在规范下完备（挂起以外都有出路：拒绝退回、
取消静默），而且 FSA 体验确实更好。但 WebView2 恰恰可能不按规范兑现——实测已见「承诺不兑现
也不报错」，完备性只是纸面假设；让未验证分支挡在已实测通道前面，把「更优」做成了「不可用」。

## 代价与后果
收益：Spark 真机开箱即用（选目录即加载）；浏览器直开不变。
代价三条：1) Spark 宿主失去句柄免重选；2) 万一浏览器预览内核真有挂起怪癖，要等满 60 秒才兜底；
3) 帮助文案口径变更（宿主=每次重选）。
验证：ui-smoke 107/107（FSA 用例块先摘 spark 桩模拟浏览器直开，7 条全过）、契约 13/13、
图标 15/15。本轮未过宿主（直开会话），无协议留痕。
