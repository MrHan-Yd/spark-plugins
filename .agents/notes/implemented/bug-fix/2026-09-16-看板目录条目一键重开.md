# Agent Note: 看板目录条目一键重开
Status: implemented
Class: bug-fix

## 背景
owner 实测反馈「点了打不开」：数据源库里目录类条目的主操作（重选目录）只藏在底部小按钮
「重新选择目录…」里，点卡片本体毫无反应；刷新后目录类又没法自动重开，空态页只给
「打开数据源库」引导，用户对着一卡片空看板不知道从哪进。

## 决策
两处入口补齐：1) 库条目卡片本体可点＝主操作（fs/http/inline 直接打开，目录类唤起目录
选择器），点按钮不算点卡片避免与置顶/删除抢事件；2) 无数据空态页改为「上次在用」一键
重开——库里最近一条是目录类时 CTA 直接唤起重选，fs/http 类自动重开失败（如未授权）时
同一按钮重试并暴露失败原因。

## 放弃方案
用 File System Access API 存目录句柄做到免重选。它才是治本，但宿主 webview 内核
支持度未实测、要新增 IndexedDB 句柄缓存与权限手势流，本轮先把「点了没反应」的死路打通。
空态同时给两个按钮（重开 + 打开库）也否了：顶栏本就有库入口，双 CTA 抢注意力。
（同日更新：FSA 通道已实测可行并落地，本节的「放弃」被推翻——
见 [看板目录句柄持久化免重选直达](2026-09-16-看板目录句柄持久化直达.md)。）

## 代价与后果
卡片整块可点后误触面变大（点卡片即唤起系统选择器），换来与直觉一致的「点卡片=打开」；
ui-smoke 空态断言「恰好一个 primary-btn」在 fresh profile 下仍成立（无库条目走旧分支）。
验证：ui-smoke 新增「点卡片进重选分支」「空态一键重开」两条断言。
