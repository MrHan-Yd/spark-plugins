# Agent Note: 反向锚点改为条件式——按宿主存在性分级留痕
Status: implemented
Class: process

## 背景

`AGENTS.md §1 反向锚点`无条件要求挂 `@trace`，但 `@trace` 的前提「会话坐标在手」只在宿主链路成立：
坐标来自宿主在 session/new `_meta.sparkTrace` 里的注入，直开的客户端会话（如 ZCode 直接开的对话）
不经 host.mjs，agent 拿不到坐标，锚点无从挂起。2026-09-16 实际发生：当天整天在直开会话里改
trace-board 与宿主相关代码，一个 `@trace` 都没挂成；更隐蔽的是 check-trace-anchors 对指向不存在
会话的 `@trace` 只静默 SKIPPED——硬写只会留下指向空气的假锚点。本笔记自身就在一次无宿主会话里
写成，是条件式降级路径的首次执行。

## 决策

留痕义务按宿主存在性分级，检测通道是宿主拉起 agent 时注入的环境变量 `SPARK_TRACE_SESSION` /
`SPARK_TRACE_DIR`（`_meta.sparkTrace` 只到协议层，多数 agent CLI 不透给模型，env 是唯一机械可靠的通道）：

- **有宿主**：`@trace s_<会话>#<事件序号> 实测：…`，坐标用
  `.agents/skills/trace-anchor/scripts/resolve-coordinates.mjs` 从 events.jsonl 取；
- **无宿主**：禁止 `@trace`，降级为决策笔记（§4）+ `@see` 文档锚点，并在回复里如实声明
  「本轮未过宿主，无协议留痕」。

判路流程沉淀为技能 `.agents/skills/trace-anchor/`（SKILL.md + references 格式细则 + scripts 坐标
解析），AGENTS.md §1 同步条件化并把 `.agents/skills` 划入义务范围；`.agents/skills` 同时加入
check-trace-anchors 校验默认根，技能自身受同一契约约束。磨顺后抽独立仓库，按
`npx skills add <owner>/trace-anchor` 形态对外发布（形态借鉴 write-notes-like-deepseek）。

## 放弃方案

1. **无宿主时让 agent 自写 trace 目录自报事件流**。最强理由：覆盖率瞬间 100%、看板单源无需改造；
   但宿主存在的意义就是 agent 不能给自己打分——自报事件流与协议观测事实混进同一张看板后真伪
   不可辨，追溯的证明力反而归零。
2. **只装 write-notes-like-deepseek 的现成 skill**。最强理由：零成本复用已验证实践；但它的笔记
   方法已在 AGENTS.md §4 落地（compliance 的 AGENT_NOTE_FORMAT 与看板聚合都是自己的实现），
   重复装载造成规则双源漂移。它被借鉴的只有打包形态：SKILL.md + frontmatter 两必填字段 +
   references/scripts 子目录 + README 一行安装命令。

## 代价与后果

收益：直开会话的「为什么」决策不再裸奔（笔记 + `@see` 兜底）；假锚点暗坑（静默 SKIPPED）被明文
封死；宿主会话的锚点前提永远成立。代价：每次写锚点多一步 env 检测；技能日后抽独立仓库时需维护
两份仓的内容一致性（本仓库为源头）。
