# Agent Note: 左轨「统计范围」只留在会话详情
Status: implemented
Class: simplification

## 背景

左轨「统计范围」（全选/全不选/仅有问题 + 逐会话勾选）此前在五个模块常驻。owner 反馈（2026-09-16 附截图）：统计范围只在会话详情里有意义，挂在其他四个 tab 上既占地又在无数据时和空态提示重复。

## 决策

左轨只在「会话详情」模块渲染显示：`setModule` 按 `mod !== 'session'` 切 `body.rail-off`，CSS 里 `rail-off` 隐藏左轨并把 `.stage` 收成单列。统计范围的状态机不变——仍然默认全选、跨模块共享；其他四个模块只是不再展示勾选界面，统计口径照常作用于勾选结果。

## 放弃方案

**每个模块保留左轨但折叠成窄条**：最强理由是用户在聚合页也能随手改范围，不用切页签。仍然不用，因为聚合页的数字（KPI/时间线/避坑/清单）本来就该先看全量，逐会话勾选是排障场景的深操作，属于会话详情的上下文；折叠条仍占一列宽度，四个模块的收益配不上常驻成本。

## 代价与后果

- 收益：其余四个模块内容满幅（数据密度提升），无数据首屏不再出现一块空的「统计范围」面板，信息架构与「范围是排障操作」的心智一致。
- 代价：在会话详情之外想改统计范围，必须先进一次「会话详情」；`.rail-off` 类与默认模块耦合（index.html 静态置 `rail-off`，setModule 动态纠正），两处须一致。ui-smoke 对左轨的断言全是 DOM 级（`#sess-list`/`#sess-count`/勾选按钮），隐藏不影响，90 项零改动全绿。
